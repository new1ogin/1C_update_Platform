# CHANGELOG.md

Журнал изменений проекта **1C_update_Platform**.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/).
Нумерация версий ведётся по [SemVer](https://semver.org/lang/ru/).

> **О нумерации версий.** В исходных кодах проекта номер версии не задаётся: отсутствуют директивы
> `#AutoIt3Wrapper_Res_FileVersion` / `#AutoIt3Wrapper_Res_ProductVersion`, а в свойствах собираемых
> `.exe` поля версии и названия продукта остаются незаполненными. Поэтому версии в этом журнале — это номера
> документированных публикаций проекта, а не версий исполняемых файлов.

---

## [0.1.0] — не опубликовано (текущее состояние)

Первый документированный выпуск. Оформление репозитория: добавлены `README.md`, `CONTRIBUTING.md`,
`CHANGELOG.md` и обновлён `.gitignore`. Рабочая логика скриптов не изменялась.

### Добавлено

- **`1C_update_Platform`** — автоматическое восстановление `techsys.dll` из прошлой версии платформы после
  установки новой:
  - отбор 64-разрядных платформ в `C:\Program Files\1cv8` по маске `\d+\.\d+\.\d+` и их сортировка по убыванию
    (`_getLastPlatform64()`, `_VersionCompare`);
  - фиксация двух последних версий как новой и предыдущей за счёт вставки в начало массива фиктивного пути
    `C:\Program Files\1cv8\9.9.99.9999`;
  - поиск файлов по маске `techsys*dll` в папках `\bin` обеих версий и проверка наличия модифицированного файла
    (с `_` в имени) у предыдущей версии;
  - перенос оригинального `techsys.dll` новой версии под именем модифицированного файла и копирование
    `techsys.dll` из предыдущей версии в новую;
  - проверка результата по размерам файлов (`$succ = 2`) и запись в журнал;
  - управление службами `1C:Enterprise 8.5 Server Agent (x86-64)` и `1C:Enterprise 8.3 Server Agent (x86-64)`:
    проверка состояния `RUNNING` через `sc.exe query`, чтение `ImagePath` из
    `HKLM\SYSTEM\CurrentControlSet\Services\…`, добавление флага `-debug` при его отсутствии и перезапуск
    службы (`sc.exe stop` / `sc.exe start` / `net start`).
- **`1C_Web_update_Publication`** — автоматическая перепубликация баз на веб-сервере и перезапуск сервера:
  - отбор платформ, пригодных для публикации, с дополнительной проверкой наличия `\bin\webinst.exe`
    (`_getLastPlatformWeb64()`);
  - обнаружение публикаций **Apache** через WMI (`Win32_Service WHERE Started = 'True'`) и разбор
    `conf\httpd.conf` регулярным выражением `_1cws_module.*/(\d+\.\d+\.\d+[^/]*)/`;
  - обнаружение публикаций **IIS** рекурсивным обходом `C:\inetpub\wwwroot` и разбором `web.config` по
    атрибуту `scriptProcessor`;
  - замена версии в конфигурационном файле на новую с предварительной проверкой существования DLL
    модуля `_1cws_module` / `scriptProcessor`;
  - перезапуск службы веб-сервера (`net stop` → пауза → `net start` → пауза → `net start`).
- **Общее для обеих программ:**
  - запуск от имени администратора (`#RequireAdmin`), работа без интерфейса (`#NoTrayIcon` у
    `1C_update_Platform`);
  - перехват критических ошибок AutoIt через UDF `OnAutoItErrorRegister.au3` с «пустым» обработчиком
    `_MyErrorHandler`;
  - журнал `<имя скрипта>.log` рядом со скриптом с защитой от повторных подряд идущих записей (`_log()`);
  - защита от параллельных запусков: хранение PID в `.ini` и завершение прежних копий (`_closeLastProc()`),
    причём имя `.ini` формируется по имени запущенного файла, поэтому для веб-скрипта используется
    `1C_Web_update_Publication_stripped.ini`;
  - директивы сборки `#AutoIt3Wrapper_Run_Au3Stripper=y` и `#Au3Stripper_Parameters=/so /rsln`.
- **`Планировщик-1C_update_Platform.bat`** и **`Планировщик-1C_Web_update_Publication.bat`** — регистрация
  заданий планировщика Windows (`chcp 1251`, удаление старого задания, `schtasks /create /IT /RL HIGHEST
  /SC MINUTE /mo 3` и `/mo 5` соответственно, запуск `AutoIt3.exe` с `*_stripped.au3` и немедленный старт).
- Переносной интерпретатор **`AutoIt3.exe`** в составе проекта — используется планировщиком для запуска
  `*_stripped.au3` без установки AutoIt.
- Документация: `README.md` (описание, таблица компонентов, структура проекта, сценарии работы по коду,
  сборка, ограничения, безопасность, план развития), `CONTRIBUTING.md`, `CHANGELOG.md`.

### Известные ограничения текущего состояния

- Обрабатываются только 64-разрядные платформы из `C:\Program Files\1cv8`; пути к каталогам установки и
  `C:\inetpub\wwwroot` зашиты в код и не вынесены в настройки.
- Для работы `1C_update_Platform` требуется, чтобы в предыдущей версии платформы уже присутствовала
  модифицированная копия `techsys_*.dll` — сам файл проект не распространяет.
- Качество переноса `techsys.dll` контролируется только по размеру файлов; проверок подписи и контрольных сумм нет.
- Обнаружение веб-серверов ведётся только среди **запущенных** служб (WMI, `Started = 'True'`); перед правкой
  конфигурации резервные копии не создаются, отката нет.
- В `.exe` не задаётся версия ресурса и название продукта; отсутствует файл `LICENSE` и явное указание
  лицензии (подробнее — `README.md`, раздел «Лицензия»).
- В коде присутствует закомментированный нереализованный функционал: `FTPEx.au3`, `$ftpserver`,
  `$ftplogin`, `$ftppassword`, `Inet.au3`, `Crypt.au3`, вызов `_SendLog()`.
- Назначение и содержимое архива `1С_upd.7z` в корне проекта не задокументированы (не указано).
- В коде остались отладочные вызовы `ConsoleWrite('@@ Debug …')`; на работе планировщика они не сказываются.
